# Our Calendar

2人で使うためのカレンダーPWA（ホーム画面に追加して使えるWebアプリ）です。予定のデータはGoogleカレンダーだけに保存し、自前のサーバーやデータベースは持ちません。

- 素のJavaScriptだけで書いています。ビルド作業はなく、外部ライブラリも使いません
- ログインしたアカウントから見えるカレンダーを、すべて表示します
- 月表示と一覧表示を切り替えられます。予定の追加・編集・削除ができます

## ファイル構成

| ファイル | 役割 |
|---|---|
| `index.html` / `styles.css` | 画面の構造と見た目 |
| `app.js` | 画面の表示と操作（カレンダー、一覧、猫・魚の絞り込み） |
| `form.js` | 予定・タスクの追加と編集の画面 |
| `dom.js` | DOM作成の小さなヘルパー |
| `auth.js` | Googleログイン（アクセストークンの取得と自動更新） |
| `api.js` | Google Calendar API の呼び出し |
| `store.js` | カレンダーと予定の読み込み・保存、2人分の予定のまとめ、キャッシュ |
| `dates.js` | 日付の計算（日本時間で固定） |
| `config.js` | **設定（クライアントID、猫と魚のカレンダー、色と名前）** |
| `privacy.html` | プライバシーポリシー（Googleのブランディング設定用） |
| `sw.js` / `manifest.webmanifest` / `icons/` | PWA用のファイル |

## ログインのしくみ

- Googleの画面遷移型ログイン（`response_type=token`）を使います
- アクセストークンは約1時間で切れます。そのとき `prompt=none` を付けてGoogleへ一瞬移動し、画面を出さずに取り直します。タップは不要です
- 取り直すタイミングは、次のとおりです
  - アプリを開いたときや、アプリに戻ってきたときに、残りが10分未満なら取り直します
  - 予定の入力画面を開くときにも、残りが10分未満なら先に取り直します
  - 保存しようとしたときにトークンが切れていた場合は、入力内容を残したまま取り直し、戻ってきたら入力画面を開き直します
- 自動の取り直しに失敗したときだけ、画面上部に「再ログイン」ボタンを出します。Googleからログアウトしていた場合などです
- この方式は、Googleが非推奨（互換性のために残しているもの）としています。使えなくなったら `auth.js` だけを差し替えます

## 設定（`config.js`）

- `clientId`：Google Cloud で作成したクライアントID
- `calendarColors`：カレンダーIDごとの色。書いていないカレンダーには、IDから自動で色を割り当てます
- `calendarNames`：カレンダーIDごとの表示名。メインカレンダーはメールアドレスで表示されるので、名前を付けたいときに使います

カレンダーIDは、アプリの「⋯」メニューで確認できます。Googleカレンダーの設定画面にある「カレンダーの統合」→「カレンダーID」でも確認できます。

## 初回のセットアップ（手動）

### 1. Google Cloud

1. https://console.cloud.google.com/ を開き、新しいプロジェクトを作ります（名前は例えば `our-calendar`）
2. 「APIとサービス」→「ライブラリ」で「Google Calendar API」を有効にします
3. 「Google Auth Platform」→「開始」を押します
   - アプリ名とサポートメールを入力します
   - 対象は **外部（External）** を選びます
   - 連絡先メールを入力して作成します
4. 「データアクセス」で、次の2つのスコープを追加します
   - `https://www.googleapis.com/auth/calendar.events`
   - `https://www.googleapis.com/auth/calendar.calendarlist.readonly`
5. 「対象」→「アプリを公開」で **本番** にします。審査は申請しません
6. 「クライアント」→「クライアントを作成」で「ウェブ アプリケーション」を作ります
   - 承認済みの JavaScript 生成元
     - `https://shota0033.github.io`
     - `http://localhost:8080`
   - 承認済みのリダイレクト URI（最後の `/` まで正確に）
     - `https://shota0033.github.io/our_calendar/`
     - `http://localhost:8080/`
7. 表示されたクライアントIDを `config.js` の `clientId` に入れます。クライアントシークレットは使いません

### 2. GitHub Pages

1. GitHubで `our_calendar` という名前のリポジトリを作り、このフォルダの中身をアップロードします
2. リポジトリの「Settings」→「Pages」を開きます
   - 「Source」は「Deploy from a branch」を選びます
   - ブランチは `main`、フォルダは `/ (root)` を選んで保存します
3. 数分後に `https://shota0033.github.io/our_calendar/` で開けるようになります

### 3. 初回ログイン（2人とも1回だけ）

1. 「Googleでログイン」を押して、アカウントを選びます
2. 「このアプリは Google で確認されていません」と表示されたら、「詳細」→「（安全ではないページ）に移動」を押します
3. 権限の確認画面で「許可」を押します

iPhoneでは、Safariで開いて共有ボタンから「ホーム画面に追加」を選び、**ホーム画面のアイコンから開いてからログインします**。ホーム画面のアプリとSafariでは、ログイン状態が別々に保存されるためです。

## パソコンで動作確認する

このフォルダで、次のどちらかを実行します。

```
python -m http.server 8080
```

```
npx serve -l 8080
```

そのあと、`http://localhost:8080/` を開きます。

## 更新するとき

ファイルを書き換えてGitHubにアップロードすれば、反映されます。Service Worker は「ネット優先」で動くので、オンラインならアプリを開き直したときに新しい版が読み込まれます。
